The CPU tail is at the Free allowance; this small mixed-route sample is not OAuth/cold-warm qualification or a performance pass.

These are not authenticated request CPU, cold/warm qualification or proof OAuth fits Free. Native binding acceptance is now observed; approximate enforcement and quota exhaustion are distinct risks.

## Independent review dispositions

The renderer now rejects production Worker names ending in -feasibility, including default production mode. Its regression checks both cases. The deploy workflow now passes the optional ALLOWED_ORIGINS_JSON setting with an empty-array default. The no-key Workerd test asserts zero outbound HTTP. These are bounded fixes; they do not establish full cross-environment isolation or hosted OAuth authentication. Live unknown-client handling additionally exposed a 500 mapping defect: reproduced red in Workerd, corrected to sanitized OAUTH_INVALID_REQUEST 400 in the provider adapter. A separate regression preserves 500 for storage failures without disclosing error text. A completed 2m54s Pro review accepted the mapping for non-release publication subject to preservation coverage. The expanded Workerd test now covers both typed provider server errors, an unexpected storage error and an existing owner-denial error; all 18 tests pass. Generic local 400 handling is not complete OAuth error-redirect interoperability.

Open release blockers from review: enforce protected branch/environment and a reviewed Stage-0 promotion record; verify distinct production KV, origins, limiter IDs and credentials; resolve the pinned provider's previous-refresh-token reuse semantics before accepting public OAuth clients; assess pre-owner-login KV writes against the daily quota; make acceptance smoke tests require the intended deployment/tool surface and version; and measure real-client refresh/revocation and authenticated CPU/KV behavior. Do not enable a public-client trial or approve production on the basis of these local fixes. The reviewed refresh concern is not a demonstrated PKCE bypass or live exploit. KV consistency prevents an instantaneous global revocation claim.
